# Задачи для агента Cursor

Давайте агенту по одной задаче: скопируйте блок «Задание» в чат Cursor (режим Agent). После каждой — проверьте на телефоне и сделайте коммит в git. Если аккаунт Cursor заблокируют, история в git сохранит всю работу.

Порядок важен: 0 → 1 → 2 → дальше по желанию.

## 0. Первый запуск и подключение

**Задание:**
> Прочитай README.md и .cursor/rules/project.mdc. Выполни `flutter analyze` и исправь все ошибки компиляции, не меняя логику и промпты. Затем помоги мне запустить приложение на телефоне. Когда запущу и выберу персонажа, посмотри лог `[RT] …`. Если сервер отвечает ошибкой или присылает события с другими именами, чем в `realtime_client.dart`, — поправь `configure()` и разбор событий под протокол Yandex AI Studio. Пример интеграции со страницы моего агента я вставлю в чат.

Если персонаж молчит, а в логе `[Safety] заблокировано: нет текста ответа` — сервер не присылает транскрипт. Тогда нужно включить его в `configure()` по документации Yandex. Чтобы в журнале была и речь ребёнка, туда же добавляется распознавание входа (`audio.input.transcription`).

**Готово, когда:** персонаж здоровается голосом, слышит ответ ребёнка и отвечает; в логе есть `*_transcript.done`; `flutter test` зелёный.

## 1. Персонаж на Rive

**Задание:**
> Замени нарисованного персонажа (`lib/ui/character_painter.dart`, `character_view.dart`) на анимацию Rive. Добавь пакет `rive`. Файл `assets/characters/bear.riv` я положу сам. Его state machine `Main` имеет входы: `mouth` (число 0–100), `listening` (bool), `thinking` (bool), `happy` (trigger). Сохрани интерфейс `CharacterView` (character, mouth, listening, thinking), чтобы остальной код не менялся. Для персонажей без .riv-файла оставь нарисованную версию.

**Подготовка:** эскиз — в Kandinsky по описанию, персонаж и state machine — в редакторе Rive (бесплатный тариф). Можно начать с готового шаблона говорящего персонажа из Rive Marketplace.

**Готово, когда:** рот двигается в такт речи, моргание и взгляд работают.

## 2. Меньше задержки: потоковое воспроизведение

**Задание:**
> Сейчас ответ собирается целиком и только потом звучит. Сделай потоковое воспроизведение через `flutter_pcm_sound`, но не теряя проверку безопасности: начинай играть звук только когда накопилось ~1,5 секунды аудио И текст, пришедший в `*_transcript.delta` к этому моменту, прошёл `SafetyFilter`. Если фильтр сработал позже — немедленно останови звук и запроси новый ответ, как сейчас. Добавь в настройки для родителей переключатель «быстрый режим», по умолчанию выключен.

**Готово, когда:** пауза между репликой ребёнка и ответом заметно короче; тесты из SAFETY_TESTS.md проходят в обоих режимах.

## 3. «Покажи, что нарисовал» — камера + GigaChat Vision

**Задание:**
> Добавь функцию: персонаж предлагает показать рисунок, на экране появляется большая кнопка-фотоаппарат. По нажатию (жмёт взрослый или ребёнок) делаем один снимок с задней камеры (пакет `camera`), уменьшаем до 1024 px и отправляем в GigaChat API с режимом Vision с вопросом «Что нарисовано на детском рисунке? Опиши одним предложением, по-доброму». Ответ передаём в Realtime-сессию как текстовое сообщение пользователя: «[Ребёнок показал рисунок: …]» и запрашиваем ответ персонажа. Фото не сохраняем на диск, удаляем из памяти сразу после отправки. Ключ GigaChat — в config.json (`GIGACHAT_AUTH_KEY`). Учти, что для GigaChat API нужен корневой сертификат НУЦ Минцифры — добавь его в assets и в доверенные для этого клиента.

**Готово, когда:** персонаж узнаёт на рисунке «солнышко», «машинку», «каракули» и хвалит.
